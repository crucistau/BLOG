前端框架选型 — 搭配 FastAPI 后端

个人技术博客 • 需要 Markdown 渲染 + 代码高亮

方案 A: React
React 19

优势

  • 生态最大 — Markdown 组件、代码高亮插件应有尽有
  • 配合 Next.js 可 SSR，SEO 优秀
  • 招聘/协作容易，社区资源多
  • TypeScript 支持最好

劣势

  • JSX、Hooks、状态管理 — 概念多
  • 配置繁琐（Webpack/Vite 需要搭建）
  • 包体积较大
  • 简单博客可能"用力过猛"
方案 B: Vue
Vue 3

优势

  • 上手最简单 — 模板语法接近原生 HTML
  • SFC 单文件组件，结构清晰
  • Vite 开箱即用，配置少
  • 文档中文友好
  • Pinia 状态管理直观

劣势

  • SSR 方案（Nuxt）不如 Next.js 成熟
  • Markdown 生态略小于 React
  • 大型项目经验不如 React 丰富
方案 C: Svelte
Svelte 5

优势

  • 代码量最少，写起来最爽
  • 编译时框架 — 无虚拟 DOM，运行时零开销
  • 包体积最小，加载极快
  • SvelteKit 提供 SSR

劣势

  • 生态最小 — Markdown/代码高亮方案少
  • 社区小，遇到问题难以搜索
  • 语法"非主流"，学了只用于 Svelte
  • 就业市场上需求低
方案 D: 纯 HTML + Alpine.js
Alpine.js + HTMX

优势

  • 没有构建步骤，直接写就运行
  • 学习成本极低
  • 页面加载最快
  • 与 Jinja2 模板完美结合

劣势

  • 不是真正的 SPA — 前后端分离不彻底
  • 复杂交互难维护
  • Markdown 需在服务端渲染
  • SEO 靠服务端模板，灵活性受限
